# Demo scripts

Real, working `.ksl` programs that exercise the terminal/game stdlib added
in `docs/roadmap.md`'s **Phase 6.6** — `List.get/set/add/size/removeAt`,
`kotlin.random`, `ksl.term`'s raw-mode input, and the `\u{XXXX}` string
escape. Unlike `../examples/` (deterministic, golden-`stdout`-diffed by
`run_examples.rs`), these are **interactive and real-time** — there is no
"expected output" to diff against, so they aren't run by ordinary
`cargo test` at all. See `demos.rs` (this crate's `tests/` directory) for
the one thing that *is* automated: a parse+static-type-check smoke test,
which needs no terminal and no timing, but also proves nothing about
whether the game actually plays correctly.

## Files

- `tui.ksl` — a tiny screen/cursor/color-control library (`clearScreen`,
  `moveCursor`, `hideCursor`, `showCursor`, `style`/`styleBold` — each one
  a combined "reset + set" in a single SGR escape — `resetColor`, and
  `COLOR_*` constants for the standard 8-color ANSI palette), built
  entirely out of ANSI escape *strings* via the `\u{XXXX}` escape — no
  native support at all, proof that `ksl.term` only needed to cover what a
  script genuinely can't do itself. Meant to be `@file:Import`ed, not run
  directly.
- `snake.ksl` — real terminal snake. `@file:Import("tui.ksl")`, WASD or
  arrow keys to steer, `q` to quit. Legend: `@` bright yellow snake, `O`
  bold bright red food, `%` white fence around the play area, `.` green
  grass.

## Running it

```sh
cargo run -p ksl-cli -- crates/ksl-core/tests/demos/snake.ksl
```

Must be run from a real terminal (not piped/redirected) — `snake.ksl`
checks `isTerminal()` itself and prints a clear message instead of
erroring if it isn't one.

## What to verify manually

- The board renders and updates every tick, no leftover garbage between
  frames (`clearScreen`/`moveCursor` working).
- `w`/`a`/`s`/`d` and the arrow keys both steer the snake in real time, no
  need to press Enter (`enableRawMode`/`readByte` working) — and the snake
  keeps moving even when no key is pressed (non-blocking read). An arrow
  key is a 3-byte escape sequence read across up to 3 `readByte()` calls
  in the same tick.
- Eating an `O` grows the snake by one; running into the `%` fence or into
  itself ends the game. Apples appear one at a time at a random interval
  (`kotlin.random`), up to 5 on the board at once — starts with 1, not
  all 5 immediately.
- Colors render correctly (`@` bright yellow, `O` bold bright red, `%`
  white, `.` green) with no leftover style bleeding from one cell into the
  next (e.g. the bold on `O` must not carry into the grass right after it,
  and the closing `%` must always be plain white, never green). If colors
  render incorrectly on some terminal, check whether that terminal's font
  has *ligatures* enabled — a real terminal was found to mis-render the
  color of everything after a `#` character specifically when its font's
  ligature rendering was on, even though the generated bytes were verified
  correct; `%` was picked as the fence character to sidestep that.
- **Terminal restoration, both ways**:
  - Quit normally (`q`) — the cursor reappears, the screen clears, and
    typing at the resulting shell prompt behaves normally again (echoes
    characters, doesn't need raw bytes interpreted by hand).
  - Interrupt with **Ctrl+C** mid-game instead — the process must still
    exit, and the terminal must still come back to normal (this is the
    specific case `ksl-cli`'s own `SIGINT` handler exists for — see
    `stdlib::terminal`'s module doc comment in `ksl-core`'s source). If a
    Ctrl+C ever leaves the shell echoing garbage/not accepting input
    normally afterward, that's a real regression here — `reset` recovers
    the terminal by hand if it ever happens.
